# ClipFetch 部署运行指南

## 一、项目简介

ClipFetch 是一个多平台视频解析/下载工具（Spring Boot 后端 + Vue 前端）。部署形态：

```
部署目录/
├── app.jar      # 后端服务（视频解析、下载、用户/鉴权等，fat jar 约 245MB）
├── dist/        # 前端静态页面（Vue 打包产物，frontend/dist 复制而来）
├── nginx/       # Nginx（托管前端页面，反向代理后端 API / WebSocket）
├── .env         # 运行配置（数据库、密钥、工具路径等，优先级高于内置默认值）
└── start.bat    # 后端一键启动脚本
```

---

## 二、环境要求

| 组件 | 版本 | 用途 |
|------|------|------|
| JDK | 21+ | 后端运行环境（`JAVA_HOME` 或 PATH 中有 `java`） |
| yt-dlp | 最新 | 视频解析核心工具 |
| ffmpeg | - | 音视频合并 / HLS 分片合并 |
| deno | - | YouTube PO token / BotGuard 挑战（仅解析 YouTube 需要） |
| aria2c | - | 多线程下载加速（可选） |
| Node.js | v24+ | CCTV h5e 解密（仅解析 CCTV 需要）、前端打包 |
| Nginx | - | 托管前端页面、反向代理后端 |

Windows 下可用项目根的 `install.bat`（管理员运行）一键写入 `JAVA_HOME`、`FFMPEG`、`DENO`、`ARIA2C`、`YTDLP`、`NODE_PATH`、`NODE_HOME` 等系统环境变量；`uninstall.bat` 移除。**写入后需重新打开命令行窗口才生效。**

## 三、启动方式

### 3.1 启动后端

双击运行 `start.bat`（脚本以后续目录为基准读取 `.env`、启动 `app.jar`）。

成功后后端 API 就绪：`http://localhost:8081/api`（端口以 `.env` 的 `SERVER_PORT` 为准）。

### 3.2 启动前端（Nginx）

进入 nginx 目录执行：

```cmd
nginx.exe
```

常用命令：

```cmd
nginx.exe -s stop      # 停止
nginx.exe -s reload    # 修改配置后重载
```

### 3.3 访问

浏览器打开 `http://localhost/`。Nginx 将 `/api/` 与 `/ws` 请求转发到后端 `127.0.0.1:8081`。

Nginx 配置参考 [deploy/nginx.conf](../deploy/nginx.conf)，关键点：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8081;
    # 视频解析/解密/下载耗时可达数分钟（CCTV 解密完成才返回响应首字节），必须放宽超时
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_buffering off;
}
location /ws {
    proxy_pass http://127.0.0.1:8081;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400;
}
```

> **超时是硬性要求**：不配 `proxy_read_timeout` 时 Nginx 默认 60 秒断开，后端解密完成写流会报"你的主机中的软件中止了一个已建立的连接"。

## 四、配置说明（.env）

`.env` 优先级高于 `application.yml` 内置默认值。

| 配置项 | 说明 |
|--------|------|
| `SERVER_PORT` | 后端端口（默认 8081，需与 nginx.conf 的 proxy_pass 端口一致） |
| `DB_URL` | 数据库连接。默认嵌入式 SQLite：`jdbc:sqlite:data/fvd.db`（相对启动目录）；支持绝对路径如 `jdbc:sqlite:D:/data/clipfetch/fvd.db`，**父目录会自动创建** |
| `DB_DRIVER` / `DB_USER` / `DB_PASSWORD` | 切换 MySQL 时取消注释对应配置，MySQL 建表由 Flyway 自动执行 |
| `JWT_SECRET` | 登录令牌密钥，**生产环境务必改为随机长字符串** |
| `YTDLP_PATH` / `FFMPEG_LOCATION` / `JS_RUNTIME_PATH` / `ARIA2C_PATH` | 各工具路径，支持 `%VAR%` 引用系统环境变量（如 `%YTDLP%`），变量不存在时回落默认值，也可直接写绝对路径 |
| `ARIA2C_CONNECTIONS` | aria2 单服务器并发连接数，默认 16（上限 16） |
| `PROXY_URL` | 出站代理，访问 YouTube/Twitter 等需要，如 `http://127.0.0.1:10808` |
| `DOWNLOADS_DIR` | 临时下载目录，相对路径以后端工作目录为基准，绝对路径如 `D:\data\clipfetch-downloads` |
| `NODE_EXE` / `CCTV_DECRYPT_SCRIPT` | CCTV 解密相关，默认 `node` 走 PATH 解析即可；脚本在 jar 内会自动解压，无需配置 |

## 五、重新打包更新

修改后端代码后重新构建并更新部署目录：

```cmd
cd backend
mvn clean package -DskipTests
copy target\app.jar ..\app.jar
```

前端修改后：

```cmd
cd frontend
npm run build
:: 用 dist\ 更新部署目录的 dist/
```

然后重启后端 / `nginx -s reload`。

## 六、前端开发模式（仅开发时使用）

```cmd
cd frontend
npm install
npm run dev
```

开发服务器运行在 `http://localhost:5173`，API 请求经 Vite 代理转发到 `http://localhost:8081`（见 `vite.config.js`，改后端端口需同步）。

## 七、常见问题

**Q1：提示 "app.jar 中没有主清单属性"？**
复制错了文件。`target/app.jar.original`（约 3MB，无依赖）不可运行，请复制 `backend/target/app.jar`（约 245MB）。

**Q2：页面能打开但接口 502？**
后端未启动，或 `.env` 中 `SERVER_PORT` 与 nginx.conf 里 `proxy_pass` 端口（8081）不一致。

**Q3：MyBatis 报错 "Parameter 'userId' not found"？**
ProGuard 混淆会抹掉 Mapper 方法参数名。修复：Mapper 参数加 `@Param("userId")` 注解（已修复过 `UserCookieMapper`，新增 Mapper 方法时注意）。

**Q4：SQLite 数据库文件在哪？**
默认在**启动目录**下的 `data/fvd.db`（start.bat 从项目根启动，即项目根 `data/`）。自定义路径直接改 `DB_URL`，父目录自动创建。

**Q5：YouTube 解析失败？**
检查 `PROXY_URL` 代理是否可用、deno 路径是否正确。出口 IP 被 YouTube 风控时需在「我的 Cookies」上传 cookies。

**Q6：下载慢？**
确认 aria2c 路径配置正确，`ARIA2C_CONNECTIONS` 默认 16。aria2 仅加速渐进式 MP4 直链，HLS/DASH 分片格式不经过它。

**Q7：CCTV 下载最后报"你的主机中的软件中止了一个已建立的连接"？**
Nginx 默认 60 秒 `proxy_read_timeout` 太短，解密数分钟后连接已被断开。按本文 3.3 节的 nginx 配置加长超时。

**Q8：环境变量改了后端读取不到？**
`.env` 中 `%VAR%` 展开依赖系统环境变量，修改后**必须重启后端进程**（已打开的窗口不继承新变量）。

**Q9：npm 报错 "无法加载文件 npm.ps1"？**
PowerShell 执行策略限制。管理员运行：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。
