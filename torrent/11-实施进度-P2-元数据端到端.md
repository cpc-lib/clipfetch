## 1. 本轮新增实际代码

- backend/src/main/java/cc/ivera/magnet/engine/metadata/PeerMetadataSession.java
  - 使用 TrackerAddressPolicy 解析和固定 Peer 目标 IP，建立同步 TCP Socket；
  - BEP3 握手，强制匹配 InfoHash 和 Peer ID，确认对端支持 BEP10 扩展标志；
  - 发送 BEP10 扩展握手，接收对端 ut_metadata 消息 ID 与 metadata_size；
  - 通过 BEP9 顺序发起 16KiB metadata 分片请求，接收响应并验证编号和总长度；
  - 将分片交给 MetadataAssembler，并使用原始 info 字节的 SHA-1 与预期 InfoHash 比较；
  - 设置连接/读超时和消息长度上限，自动关闭 Socket，避免泄漏连接。
- backend/src/test/java/cc/ivera/magnet/engine/metadata/PeerMetadataSessionTest.java
  - 使用本机 ServerSocket 构建模拟 Peer；
  - 模拟从 BEP3 握手、BEP10 扩展协商到 BEP9 ut_metadata 请求/回复的完整过程；
  - 断言最终得到的原始 info 字典字节与预期完全一致。
