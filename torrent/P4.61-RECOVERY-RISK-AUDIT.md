# P4.61 多节点恢复风险审计

日期：2026-10-15。Native 自动接管仍禁用。

## 本轮实际测试
- 新增 `NativeTaskLifecycleServiceTest.naturalLeaseExpiryConcurrentRecoveryFencesExactlyOnce`：使用真实时间的 1 秒租约，不直接修改数据库的 lease_until；到期后 4 个线程各持独立 SQLite/MyBatis Session 并发隔离同一个 RUNNING 任务。
- 测试要求：未过期时隔离失败、过期后恰有一个成功、任务 PAUSED、对应 Revision 的 FENCED_EXPIRED 审计恰好 1 条、旧 Epoch/Instance 再也不能通过 requireFence。
- 上述专项与完整 `mvn -f ... -q test` 均 Exit Code 0。
- MySQL 故障时本地 Worker 的 fail-closed 行为由 P4.59 `databaseOutageAlsoFencesWorkerFailClosed` 既有单元测试覆盖；**本轮没有进行真实 MySQL 网络断连注入**。

## 排查结果与尚未修复的生产阻断
1. **时钟偏移**：`isLive/isExpired/renew` 通过应用 JVM 的 UTC 时间与数据库持久化值对比。多服务器间时钟偏移会导致过早回收或租约延长。本轮未改为数据库权威时钟；真正跨主机环境不可上线自动接管。后续需要统一由数据库产生/比较 lease_until，且 SQLite 与 MySQL 分别适配。
2. **不同物理主机磁盘互斥**：目前 `FileLock` 只能验证协作进程共享相同可支持锁的目录；网络文件系统 NFS/SMB 已拒绝，两个独立主机的相同本地目录不代表共享 Checkpoint。必须有明确的存储一致性/分布式令牌协议才能开放跨主机接管。
3. **MySQL 短暂断连**：心跳本地保护 fail closed 已测试，但未做断网→恢复→旧 Worker 无法复活的真实双机故障注入；重试行为需安全评估。
4. **竞争规模**：本轮 4 路同机 SQLite 并发通过，不等于 MySQL 四个 Boot 实例或跨机压测通过。SQLite Mapper 的独立 auto-commit Session 不等同 Spring 事务的真实 COMMIT 边界；P4.55/56 另覆盖 Spring/MySQL 事务提交顺序。
5. **自动接管**：严格禁用；所有测试为显式人工调用隔离/恢复。

## 本轮范围结论
提高自然租约到期与竞争场景的回归覆盖；未宣称两台真实服务器网络风险已修复。下一阶段优先完成 DB 权威时钟适配与两台真实主机的网络故障注入，再评估启用条件。
