## 二、已新增接口

- GET /api/magnet/native/engine/health：报告 configuredEnabled、ready=false、downloadAvailable=false、stage=P0-P1。
- POST /api/magnet/native/magnet/inspect：请求 JSON 为 {"magnetUri":"magnet:?xt=urn:btih:..."}，校验并规范化 InfoHash，返回展示名/Tracker 数；不进行元数据网络解析。
- POST /api/magnet/native/torrent/inspect：multipart file 上传 .torrent（大小上限为 8MiB 或配置值），通过原始 info SHA-1 校验并返回只读文件树、Piece 数及总字节；不保存、不下载。
- 均沿用现有 JWT 拦截器与 ApiResponse，未设置匿名白名单。
- 暂未新增 Native 创建下载任务的 REST 路由；不可在未实现 Peer 下载时返回“成功创建的下载任务”。

## 三、数据隔离结果与设计边界

- 新表 torrent_native_task 的唯一键为 task_uuid，info_hash 只有普通索引。
- 即使两个用户拥有相同 info_hash，也有独立 task_uuid、selectedFiles、verifiedSelectedBytes、revision 和目录。
- XML Mapper 查询/更新/删除必须包含 user_id 和 task_uuid；逻辑删除 deleted=id。
- 保留旧 magnet_download_task 全局 InfoHash 唯一约束，让 legacy qBittorrent 任务照常运行。
- 新 native 任务尚无真实 Peer 会话、下载状态持久化与端到端用户操作，所以“协议层已可下载”属于错误声明。

## 五、下一轮 P2 必须实施

1. HTTP Tracker 客户端：二进制 InfoHash percent-encoding、compact peer list、超时、限制出站地址。
2. UDP Tracker：connect/announce、transactionId 匹配与重试。
3. DHT：KRPC/BEP5、k-bucket、迭代 get_peers、限流与超时。
4. Peer TCP 非阻塞通信：SocketChannel+Selector，真实握手、维护状态、限额。
5. BEP10 扩展协商，BEP9 ut_metadata 16KiB 分片重组，并且对原始 info 字节 SHA-1 做完整校验。
6. 已验证 metadata 的只读共享缓存；不同用户各自拥有独立解析历史与后续业务任务。
7. 构造离线测试 Tracker/Peer/DHT Fixture；执行合法授权资源的真实集成测试。

P2 的验收是可以用自主协议栈解析合法磁力得到真实文件列表；仍没有 Piece 下载及存储，不能视为完整引擎。
