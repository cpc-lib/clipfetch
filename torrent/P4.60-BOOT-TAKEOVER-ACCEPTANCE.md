# P4.60 两个完整 Spring Boot 应用上下文接管同一 MySQL Native Task

日期：2026-10-15。自动接管功能保持关闭。

## 已实际验收
- 两个独立 Java 子进程使用 `SpringApplicationBuilder(ClipFetchApplication.class).web(WebApplicationType.NONE)` 加载完整应用 Spring Bean（包括 MyBatis Mapper、事务管理器和实例心跳），连接同一隔离 MySQL 8.0。
- Native Task ID 一致，任务路径与 Checkpoint 一致；受控合成 Peer Fetcher 不连接外网。
- 实例 A 的 `NativeTaskRoundRunner.runFenced` 领取 READY，提交 Piece 0、执行持久进度 CAS；开始下一 Piece 时 `Runtime.halt(37)` 注入崩溃，保留 RUNNING 状态和实际磁盘 Piece。
- 实例 B 在租约有效时拒绝隔离，随后测试夹具**明确手动写入过期租约**，再由真实 Spring Bean `NativeExpiredOwnerFenceService` 在文件锁和 `TransactionTemplate(REQUIRES_NEW)` 下隔离并审计。
- 实例 B 执行 `reconcileStopped`、`prepare`、重新 `runFenced`，只拉取 Piece 1。最终 MySQL COMPLETED、verified=8、execution_epoch=2、FENCED_EXPIRED 恰好 1 行。
- 经修复的实际问题：Flyway 默认配置覆盖测试默认值；需高优先级命令行禁用测试数据库 Flyway；测试夹具的跨表隐式 UUID 比较因 MySQL 不同排序规则失败，改用参数化同表查询与独立审计查询。

## 范围限制
- 两个完整 Boot **无 Web 服务模式**运行，测试入口只存在 src/test，不创建生产 REST 操作。
- 不使用外网 BT Peer，网络 TCP/Tracker/DHT 未在本测试涵盖。
- 租约到期使用受控人工注入，没有等待完整 TTL 自然到期，也未测试自动扫描和自动调度。
- 文件锁在本机 Windows 的本地目录上验证；不能代表 NFS/SMB 多机。
- 数据库与两个 Boot 实例在单台 Windows 主机中，尚非两台独立服务器。
- 请勿据此启用自动接管；生产 Native Worker 开关保持原样。

## 执行和日志
- 真实 MySQL 8.0 独立 Docker 测试数据库，执行 V13、V19、V20、V21。
- 默认测试会跳过：`NativeBootTakeoverIT` 仅在 JVM 系统属性 `clipfetch.mysql.bootTakeover=true` 时执行，需环境变量 `CLIPFETCH_MYSQL_IT_PASSWORD`。
- 测试 stdout/stderr：`backend/target/native-boot-takeover-diagnostics/<task-uuid>/`。
