## 核心实现

- `PeerRoundConnectionPool.java`：按 Peer 独占 TCP 读/写；支持多 Piece Block 批量 REQUEST、RESPONSES、CANCEL，实时统计接收数据；短时间 Socket 输入探测避免把部分 BEP3 帧误当成下一帧；出现混合 End-game 或未处理请求时退役 Socket。
- `PeerPieceDownloadSession.java`：用认证过的任务 Round/Actor 作用域复用 TCP 池的 multiplexed IO；禁止无任务作用域运行。
- `PeerMultiplexedRound.java`：共享一个任务级 Block Mailbox；每个 TCP Actor 向该 Mailbox 请求工作并持有各自的 TCP 流；写入 `PieceBlockAssembler` 后做最终 SHA-1 校验，传递结果给 owner；异步任务和 Socket 在取消/超时后清理。
- `PeerBlockMailbox.java`：一个主 Block 租约 + 最多一个 end-game 备用租约，记录已派发来源，禁止伪造重复应答；潜在迟到的 Socket 标记不可重用。
- `PieceDownloadCoordinator.java`：新增 `enableMultiplexedMailbox` 和经过 guard/fence 的实验性 owner 提交路径。原来的 Piece 级调度保留，并仍是默认。
- `NativeTaskWorkerRoundService.java`：仅对已有连续 Task 及主动启用的实验模式切换。
- `PeerBlockMailboxFrames.java`：BEP3 REQUEST/PIECE/CANCEL 的严格帧读写适配。

## 已完成的真实 TCP 测试

1. `PeerMultiplexedRoundIntegrationTest.twoTcpPeerActorsFetchDifferentPiecesOverOneSocketEach`：两个模拟 Peer 分别拥有两个不同 Piece；单条 TCP Socket 接收多个 Piece，最终 4 个 Piece 的 SHA-1 全部通过，连接新建数为 2。
2. `PeerMultiplexedRoundIntegrationTest.optedInCoordinatorStillUsesOwnerOnlyCheckpointAndFencedGroupCommit`：通过 `PieceDownloadCoordinator.runRound` 真实入口执行 opt-in，多路网络与父线程提交分离；四个 Piece 分两组持久化，进度分别为 8 bytes、16 bytes，最终 staging 为空。
3. `PeerMultiplexedEndgameIntegrationTest.fastEndgameBackupWinsAndBothPossiblyStaleSocketsAreRetired`：真实 TCP 延迟主请求，另一个 Peer 在 2 秒超时阈值后参与 Backup，先返回有效 Block 并验证；两条可能含迟到帧的 Socket 不能被后续轮次借用。
4. `PeerBlockMailboxTest`、`PeerBlockMailboxFramesTest`：多 Peer 不重复分配主请求，防注入/不接受未知来源，超时主备请求只认第一个有效应答，输出 BEP3 CANCEL。

以上均为环回模拟连接，不等于 qBittorrent 的真实公网带宽增益。

## 安全、资源和落地限制

- 新路径只会在显式 opt-in、原 task scope 有效、Peer >=2 时运行；否则保持经过验证的原有 Piece 路径。
- 单轮至多 32 Piece、64MiB 内存预算与 16 Peer Actor；PeerBlockMailbox 每 Peer 最多 64 Block 请求，TCP Actor 每次最多补齐 16 个请求。
- 不允许一个 Actor 共享其他用户的 Socket；已验证整 Piece 方可交 owner 写 Checkpoint。
- 关闭/暂停/过期时，通过现有 ChildThread/Task Actor abort 通路清理 Socket；对存在 end-game 迟到数据可能的 Socket 强制关闭，不放入跨轮复用池。
- 当前不修改 .env 实际密钥和运行时设置，不重启在线 Spring Boot，不开公网监听。
- 实验通道目前可能比原路径更慢，因为新增调度/数据同步和限制了 16 Actors；必须实测后调整，**不能声称已经超过 qBittorrent**。
