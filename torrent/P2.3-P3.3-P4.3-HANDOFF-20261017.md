## 安全与数据边界

1. 邮箱/用户/任务等应用层身份**不能**从标准 uTP SYN 推导出来。未经应用层 torrent InfoHash / 用户身份校验的公网 uTP SYN 不能自动进入任务；当前 Registry 只允许显式注册的 task-scoped sessions。
2. Block Mailbox 中的数据是未完全验证的 Peer 原始数据，只允许交给 `PieceBlockAssembler` 后再经整个 Piece 哈希校验、Checkpoint fsync 和 fenced CAS，绝不能直接记为下载完成或写入跨用户 Verified Piece Store。
3. 每个 Block 最多有一个主租约和一个备用租约。Block 一旦获胜就释放所有容量、产生协议 CANCEL，迟到的已授权备份包不会二次提交，未授权来源不能注入该 Block。
4. 超时、断连、停止的 Peer 不能跨任务传递 Block 数据；Registry 的会话键包含 owner、task、IP:port、receiveId。所有内存队列都必须随任务生命周期清理。
5. 本次新增 uTP 代码没有在 Spring Boot 中绑定任何 UDP 监听，也没有开放防火墙/NAT、没有重启下载任务。

## 继续开发路线

### P2.4：安全接线生产 TCP 下载

分阶段重构 `PeerRoundConnectionPool` 为每任务、每 Peer 一个长生命周期 socket reader/writer actor。
- 同一 Socket 上按 `(pieceIndex,begin,length)` 解复用多个 Piece 的并发请求，检测和拒绝来自错误任务或未经请求的报文。
- 为多 Piece 规划有限总缓存预算，保留既有 owner 的 Piece SHA1、Manifest/Checkpoint、DB CAS fencing。
- 在配置中增加实验开关，默认关闭，通过 A/B 同一个官方 Ubuntu Torrent 的 5min 指标证明进度、内存及取消可控后才能默认启用。

### P3.4：真实 End-game 多 Peer 抢占

将 `PeerBlockMailbox` 与多个真实 socket actor 集成，收到有效首个响应后向败者发送 BEP3 CANCEL，日志输出 redundant wire bytes / endgame wins / p95 Block RTT；并在哈希失败时回收整个 Piece，而不是错误信任多个 Peer 拼接的 Block。

### P4.4：真实 uTP 互操作

补齐 SYN 超时重传 / 握手序号状态、可靠 UDP socket stream、BEP29 双向 ACK/SACK、窗口与拥塞回退、UDP demux、MTU 和半关闭状态；建立公开 libtorrent/uTP 客户端互操作矩阵后才允许生产开关开启。入站公网监听仍需明确运维许可。
