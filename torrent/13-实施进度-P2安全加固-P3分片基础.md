## 1. 本轮 P2 加固

### 地址过滤
调整 backend/src/main/java/cc/ivera/magnet/engine/tracker/TrackerAddressPolicy.java：
- 保持默认拒绝内网/回环/链路本地/多播以及不可信混合 DNS 解析结果；
- 额外拒绝文档测试 IPv4 段、100.64/10 共享地址空间、198.18/15 基准测试、192.0.0/24、192.88.99/24 等；
- 全球单播 IPv6 2000::/3 允许基本公共地址，明确拒绝 2001:db8::/32 文档地址、2001::/32 Teredo、2002::/16 6to4 等特殊用途地址；
- 继续由客户端使用解析后固定 IP 建连，不通过主机名再次选择其他目标；
- 仅测试 fixture 使用 new TrackerAddressPolicy(true)，生产默认必须 false。

注意：当前策略是保守拒绝清单，不等于完整的 IANA 实时特殊用途地址注册表。生产上线前必须全面审计 NAT64、IPv4 mapped IPv6、企业代理、最新分配段与连接实际目标。

### 元数据连接绝对截止时间
调整 backend/src/main/java/cc/ivera/magnet/engine/metadata/PeerMetadataSession.java：
- 采用 monotonic System.nanoTime 全传输 deadline；
- BEP3 握手与每个 BEP10/BEP9 响应在相同整体 deadline 内，读取时持续更新剩余 Socket SO_TIMEOUT；
- 替换 readNBytes 等仅受单次 Socket 超时保护的长读，防止对端不停发送零星字节长期占用线程；
- 保留消息大小、消息数量、元数据总大小限制，以及 InfoHash SHA-1 校验；
- 检查线程中断并及时返回 IO 异常。

限制：Java 阻塞 Socket 的写路径和域名解析本身不保证严格硬截止；本轮还未实现整个 DiscoveryService + Resolver 从开始到结束的统一绝对时间预算，也未补齐网络取消/并发池控制。

### HTTP Tracker 绝对截止时间
调整 backend/src/main/java/cc/ivera/magnet/engine/tracker/HttpTrackerClient.java：
- 将连接、HTTP Header 和完整 Body 的读取纳入同一整体 deadline；
- 即使 Tracker 慢速持续发送字节，客户端也不会无限等待；
- 仍限制 16KiB Header 与 2MiB Body、拒绝 HTTP 跳转与 Transfer-Encoding；
- 依旧只支持明文 HTTP。HTTPS、chunked 响应必须在后续单独实现并测试。

## 2. P3 初始 Piece 校验与请求规划

新增：
- backend/src/main/java/cc/ivera/magnet/engine/piece/PieceBlockPlanner.java：
  根据 TorrentInfo 与用户选中的 file index，计算 wantedPieces；文件边界重叠时必须请求并校验整个 Piece；每个 Peer 请求块最多 16KiB；支持最后一个不完整 Piece。
- backend/src/main/java/cc/ivera/magnet/engine/piece/PieceHashVerifier.java：
  校验索引、Piece 实际长度，并与 TorrentInfo 原始 pieces 数组中的对应 20 字节 SHA-1 做常量时间比较；不能以“纯内存 SHA-1 通过”直接计入已落盘进度。

注意：**这只是规划和验算，没有网络请求执行器、Piece BlockAssembler、FileChannel 分段持久化、断点恢复，也未产生真实下载任务状态或进度。**
