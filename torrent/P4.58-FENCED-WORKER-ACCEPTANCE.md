# P4.58 Native Fenced Worker 受控 Peer 验收

## 本轮实际执行
- 新增 `fencedWorkerRoundUsesSyntheticPeerAndPersistsVerifiedPieces`，通过 `PieceDownloadCoordinator.Fetcher` 提供确定性合成 Piece，走生产 `NativeTaskRoundRunner.runFenced`、真实 Checkpoint 校验/写盘、SQLite Mapper Revision/Epoch CAS。
- 第一轮只提交 Piece 0，任务转 PAUSED 且 VerifiedBytes=4；准备恢复后使用新的 InstanceId 第二轮只请求 Piece 1，最后 COMPLETED=8、磁盘复核=8。
- 新增 `fencedWorkerRejectsLostHeartbeatBeforeClaim`：注入健康检查失败，任务仍 READY，磁盘零 Piece。
- 不连接真实 BT 网络，也不使用第三方内容；未启用自动接管。

## 验收边界
- P4.57 已在真实双 Spring Boot 进程+同一 MySQL 验证实例独立注册与心跳续期；P4.56 已用两个独立 Java JVM+真实 MySQL/JDBC 与 Spring TransactionTemplate 验证提交前终止、提交后读取及审计原子性。
- **本轮未把全部模块串在两个完整 Spring Boot 进程里的同一任务上运行**；受控 Peer 的 Worker Round 仍为 SQLite 单进程专项测试。不能报告为完整 MySQL 双 Boot Worker E2E。
- 新 InstanceId 和新的 Epoch 在现有 SQLite 跨 JVM 生命周期测试中验过；本轮 synthetic Peer test 验证执行路径与磁盘重开，但未验证实时实例租约的数据库有效性。
- 部署端依旧禁止 NFS/SMB/UNC 已知共享存储路径，自动接管/自动下载关闭。

## 下一步阻断项
1. 建立仅测试环境启用的任务触发/进程协调通道，在双 Boot 进程上接入本地受控 Peer，避免真正公网下载。
2. 在真实 MySQL 双 Boot 运行中注入心跳过期、进程崩溃、重试并记录同一任务各轮 Epoch、磁盘与审计；严格保证恢复事务提交后释放文件锁。
3. 旧 Worker 兼容入口仍保留在配置和源码；上线前评审后移除。
