- backend/src/main/java/cc/ivera/magnet/engine/dht/KrpcCodec.java

  - UDP 单包大小限制 1500 字节；
  - **暂未实现真实 DatagramChannel 发送/接收、令牌、错误包处理、迭代 get_peers**。

## 三、设计与上线限制

- TrackerProtocol 目前只支持 **compact IPv4 HTTP peers**；非 compact / peers6 返回不支持或尚未解析。
- 协议解析本身**不执行** DNS/IP/SSRF 过滤；开发 HTTP/UDP 客户端时必须在每次解析域名、重定向和连接前验证公网目标地址（本地 fixture 使用显式测试模式）。
- DhtRoutingTable 未做完整 Kademlia k-bucket 节点替换/活性检测，严禁将其当成已完成 DHT 引擎。
- KrpcCodec 的 error 消息目前只识别外层结构，不支持完整错误 payload 的解析；真实网络层实现前必须补齐。
- HTTP Tracker 的 client 尚未实现；UDP Tracker 也仅有报文编解码，尚无重试、超时、网络 I/O。
- 尚无 BEP9 ut_metadata、Peer Reactor、Storage 和 Piece 下载；无法获取真实 Magnet 文件树或下载文件。

## 五、与多用户进度隔离的关系

- infoHash 仍是内容标识，不是任务 ID。
- DHT 和只读 Peer 候选可共享；下载会话、文件选择、进度计数、暂停/恢复、临时文件、断点全部要按 taskUuid+userId 独立。
- 当前 P2 网络基础不会写入用户进度，更不会错误合并多用户任务。
- 必须在 P3/P4 实现每任务独立的 PeerSession、PieceScheduler、存储、状态机及 TaskActor。
